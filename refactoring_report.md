# Отчёт по рефакторингу

Конвейер собран с нуля по структуре практики 6.1. Исходной реализации модели в проекте не было.

| Этап | Функция | Ответственность |
|---|---|---|
| Загрузка | `load_data` | Читает паспорт TDG, исходный список абонентов и даты прекращения обслуживания |
| Подготовка | `preprocess` | Читает суточные партиции, очищает записи и строит признаки для каждого среза в Spark SQL |
| Обучение | `train_model` | Обучает XGBoost на CPU и сохраняет модель с параметрами скоринга |
| Оценка | `evaluate` | Считает качество вероятностей и ранжирования на отложенных срезах |
| Сборка | `main.py` | Читает конфигурацию, запускает обучение или скоринг и публикует результаты |

Пути, даты срезов относительно начала набора, горизонт, длина окон, минимальное покрытие источников, ограничения значений, признаки, регуляризация и порог вынесены в `config.json`. Обучение детерминировано и не использует случайное разбиение. Для набора TDG начальное состояние записывается в метрики из паспорта.

При повторном обучении временный каталог собирается рядом с результатами. Каталог публикуется целиком под идентификатором, вычисленным из файлов. Затем атомарно обновляется `latest.json`. Одинаковые результаты используют один каталог. Скоринг заменяет витрину за заданную дату без добавления строк. Отдельные запуски с различающимися результатами сохраняют собственные каталоги.

Главные сложности возникли на границах времени и при качестве выгрузок. Тридцатидневные окна разметки разделены по времени. CDR, поступившие в момент среза или позднее, для него исключаются. При отсутствии даты доставки файла поздние партиции остаются за пределами исторической оценки. Повреждения фиксируются в журнале и отчёте качества, а недостаточное покрытие останавливает расчёт. Поле `retention_contact` исключено на этапе чтения.

Spark обрабатывает сырые события распределённо. При дублях по ключу в пределах дневной партиции Spark выбирает одну запись по фиксированному порядку полей. Для каждого источника агрегаты строятся по дате среза и ключу абонента. В драйвер передаётся готовая матрица признаков, с которой работает XGBoost.

Тесты покрывают обе границы горизонта, удаление уже ушедших абонентов, запаздывание CDR, дедупликацию обращений, исключение поля удержания, защиту от пересечения горизонтов и расчёт метрик при одинаковых вероятностях.
